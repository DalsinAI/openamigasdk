# SDK and OpenNDK audit — 24 October 2026

The game-build SDK lacked curl, even though OpenBrowser already had a working
curl port. These are separate build environments. OpenAmigaCurl supplies
static libcurl and nghttp2, not a curl Shell command (`BUILD_CURL_EXE=OFF`).
Its HTTP/HTTPS-only feature selection is intended for OpenBrowser; other
applications must check the calls/features they need before reusing it.

## Native interfaces

`manifest.json` now pins the reviewed current OpenRTG, OpenSocket,
accontrol.device and print interfaces, and adds the existing OpenTLS/OpenCrypto
headers. The gathered files remain owned by those repositories. OpenNDK is
part of this repository, not another independently versioned NDK download.
The installed local SDK was older than this main branch.

OpenNDK's generated-file, standalone C/C++ header, all-headers, size/layout,
call-disassembly and link-library tests passed on the isolated checkout.
The test library contained 1,499 objects. C used m68k-linux-gnu GCC;
C++ used the verified open3 Amiga G++.

The installed vendor NDK was compared read-only with open3: 459 structures,
7,528 shared constants and 76 SFDs. No missing structures or constants, and
no differences in call names, offsets or registers. The comparison returns
1 because it reports two POSIX aliases (`timeval.tv_sec/tv_usec`, sharing
the native fields' offsets) and GetUnit's DiscResourceUnit/DiskResourceUnit
type-name difference. These are recorded differences, not a clean comparator
pass. No vendor files were copied.

Still absent: `dos/ansiio.h`, `reaction/reaction_author.h`,
`resources/ciabase.h`. The vendor TextEdit header cannot compile alone due
to its own missing include. Assembler structure includes, debug.lib,
autodocs, vbcc inlines and OS4.1 coverage also remain outside completion.

## Curl overlay

`tools/build_curl_sdk.py` exports pinned curl/TLS sources, checks the open3
compiler receipt, uses a new output directory, and builds an SDK overlay
with a complete OpenNDK header set ahead of the compiler's older NDK.
It does not alter the stove, source caches or installed SDK. Existing zlib
inputs and all output files are hashed in its receipt.

GCC ignores `-I` for a directory also passed as `-idirafter`. Mixing those
let older hook declarations win and caused a real HOOKFUNC compile error.
The helper removes inherited NDK_INCLUDE and uses one explicit SDK system
include directory, keeping the complete native header set together.

```sh
python3 tools/build_curl_sdk.py --stove /path/to/open3-stove \
  --curl-source /path/to/openamigacurl --tls-source /path/to/openamigatls \
  --tarballs /path/to/curl-tarballs --dependencies /path/to/target-zlib-prefix \
  --out build/curl-sdk-new --jobs 2
```

The source pins and tarball SHA-256s are enforced by the helper and upstream
build. The output is `build/curl-sdk-new/sdk`, with include/, lib/, curltest
and licence notices; receipt.json/build.log sit beside it. Use this prefix
explicitly for consumers, with a matching 68040/FPU ABI. Soft-float consumers
need a separate qualified build. TLS is provided at runtime by opentls.library;
no runtime deployment or network qualification is implied by compile/link.

Remaining integration gates: Enigma still needs Xerces-C; curl's transitive
static dependencies must be passed to its build, then game compile/runtime
qualification. SDL/OpenGPU/OpenAL must retain their own SDK/runtime version
and ABI gates; this change does not certify every Open-family library.

## Source checks in public CI

The full `tools/gather.py --check` requires access to the private guest source
repository. It was run locally against every pinned source. The manifest now
records SHA-256 for every gathered output (including generated FD files).
Public CI uses `--offline-check`, which requires a complete receipt and checks
all committed bytes. The online check also verifies those hashes against the
pinned sources. Advancing a pin requires the full online check; offline hashes
alone do not establish where a newly supplied file came from.
